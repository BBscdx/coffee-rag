# 咖啡产业知识问答助手

基于 RAG 的咖啡产业问答助手：先检索、再作答，回答必须引用资料、数字必须来自知识库。
用一套可复跑的评测体系度量回答质量，两轮 36 次回答零幻觉。

## 项目简介

- **做什么**：用户问云南/贵阳的咖啡产业问题（面积、产量、出口、门店......），系统先从本地知识库检索相关段落，再交给 DeepSeek 基于检索结果作答。
- **知识库**：11 篇咖啡产业资料（官方答复、产业报告、海关数据、调研纪要、新闻报道），每篇标注来源与日期（发布/统计时点 2023-2026，早期历史仅作为背景）。
- **凭什么可信**：用 18 题提问集 + 检查点判定 + 幻觉数字扫描评测回答质量，评测结果可复跑、可复核。

## 解决了什么问题

- **通用 LLM 会编造数字**：直接问大模型“2025 年云南咖啡产量多少”，可能得到查无实据的数字。本系统强制模型只基于检索到的资料作答，答不出就拒答，不编造。
- **产业数据口径混乱**：同一指标存在“初步口径”与“最终口径”（发布会初步数 vs 大会最终数），本系统要求模型说明口径差异、绝不混用。
- **回答无法溯源**：每个回答强制标注 [资料 N]，读者可以回到原始文档逐条核对。

## 工作原理

```
提问
 → ① 检索：TF-IDF + 余弦相似度，30 个知识块取 top_5
 → ② 组装：检索块 + 反幻觉规则，拼进 prompt
 → ③ 生成：DeepSeek 作答，强制标来源
 → ④ 评测：检查点判定 + 幻觉数字扫描（可复跑）
```
- 检索器与评测脚本均为手写实现，不依赖现成框架
- SYSTEM_PROMPT 五条反幻觉规则：绝对忠实于资料 / 强制标来源 / 拒绝编造 / 口径差异必须说明 / 数字纪律

## 问答示例

**问**：2023 年云南省咖啡种植面积多少？

**答**：2023 年云南省咖啡种植面积为 114.6 万亩，产量 14.6 万吨，均占全国的 98% 以上。该口径为云南省农业农村厅答复中引用的“统计数据”（2023 年自然年）[资料2]。需注意：该数据与 2024 年报告口径（119.31 万亩、15.02 万吨）分属不同年份，不可混用[资料1]。

一个回答同时展示三件事：数字可溯源、口径差异主动说明、来源可核对。更多问答与失败案例分析见 [docs/评测报告.md](docs/评测报告.md)。

## 快速开始

1. 克隆仓库并安装依赖：

   ```bash
   git clone https://github.com/BBscdx/coffee-rag.git
   cd coffee-rag
   pip install -r requirements.txt
   ```

2. 在项目根目录新建 `.env` 文件，填入 DeepSeek API Key：

   ```text
   DEEPSEEK_API_KEY=sk-你的密钥
   ```

   `.env` 已被 .gitignore 排除，不会上传到 GitHub。

3. 启动问答界面：

   ```bash
   streamlit run app.py
   ```

   浏览器自动打开本地页面；每个回答都带检索留痕与 [资料 N] 来源标注。

## 项目结构

```
coffee-rag/
├── app.py              # Streamlit 问答界面（本地运行入口）
├── rag.py              # 核心模块：切块 → TF-IDF 检索 → DeepSeek 问答
├── requirements.txt    # 依赖清单
├── knowledge_base/     # 11 篇咖啡产业资料，每篇标注来源与日期
├── notebooks/          # 开发记录：切块 → 检索 → 问答（迭代草稿）
├── eval/
│   ├── checks.py           # 18 题评测标准（must/any 检查点）
│   ├── run_eval.py         # 跑批脚本：判定 + 检索覆盖 + 幻觉扫描
│   ├── report_baseline.csv # baseline 评测结果（11/18）
│   └── report_v2.csv       # v2 评测结果（15/18）
├── docs/
│   ├── 提问集.md           # 18 个评测问题（五类，含期望答案）
│   └── 评测报告.md         # 完整评测报告：设计 / 诊断 / 结论 / 展望
└── README.md
```

## 评测结果

| 版本 | 检索 top_k | 判定结果 | 幻觉 |
| :--- | :---: | :---: | :---: |
| baseline | 3 | 11/18 | 0 |
| v2 | 5 | 15/18 | 0 |

- 所有失败都是拒答/漏写，没有一个编造的数字
- 剩余 3 题根因是能力边界而非 bug：题 5 陷阱命中（模型忠实但不做跨文档推导计算）、题 7/14 受检索深度限制
- 每道失败题的诊断与归因见 [docs/评测报告.md](docs/评测报告.md)

## 技术栈

Python 3 · Streamlit（界面）· Jupyter Notebook（开发记录）· jieba（分词）· 手写 TF-IDF + 余弦相似度（检索）· DeepSeek API（生成，OpenAI 兼容接口）· python-dotenv


## 协作方式

本项目的评测标准（checks.py）由我定义，跑批脚本（run_eval.py）与诊断脚本由 Claude Code 编写，诊断结论与评测报告由我撰写。过程中 Claude 的两起预测被实验证伪：预测 k=5 能救题 5/7，实测不能；“咖啡馆/咖啡分词颗粒度错配”假说被逐词贡献实测推翻（真实原因是标点当词）。AI 协作的价值不在“不犯错”，在于错误被实验抓住、留下证据、写进报告。
